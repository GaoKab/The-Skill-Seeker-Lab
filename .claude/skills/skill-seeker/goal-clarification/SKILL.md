# Goal Clarification

Vague goals produce vague recommendations. Before designing a learning path, force the goal to be specific enough that you'd know whether it was met in 90 days.

## Common vague goals → clarifying questions

| Vague goal | Ask |
|------------|-----|
| "Get into AI" | Which role? (engineer, PM, researcher, ops). What's your current job? What would success look like in 6 months — a job offer, a project shipped, a course completed? |
| "Change careers" | From what to what? Which adjacent skill bridges them? What's your timeline (and is it driven by income, burnout, opportunity)? |
| "Learn to code" | For what — a job, a side project, a specific tool at work? Frontend, backend, data, scripting? Do you have a project in mind? |
| "Become a better marketer" | Which channel? B2B or B2C? Are you optimizing an existing role or pivoting? |
| "Learn data science" | Analyst (SQL + dashboards), scientist (stats + ML), or engineer (pipelines + infra)? |
| "Start a business" | What kind — agency, SaaS, content, services? What's the first $1 of revenue look like? |

## Clarification frameworks

Pick the one that fits the user's situation:

- **Outcome-anchored** — "What will be true in 90 days that isn't true now?" Forces a measurable endpoint.
- **Job-spec** — pull a real job listing they'd apply to; the required skills become the target.
- **Project-spec** — pick one concrete thing they'll have built/shipped; the skills are whatever that project needs.
- **Income-anchored** — "What's the smallest thing someone would pay you for?" Useful for career-change/freelance goals.
- **Decision-anchored** — "What decision will this skill let you make?" Useful when "learning" is really "evaluating."

## Output of this sub-skill

A single line of the form:

> "By <date>, I will <verb> <concrete artifact/outcome>, measured by <test>."

Examples:

- "By July 30, I will ship a Streamlit app that classifies my email inbox, measured by it running on my laptop and processing 100 real emails."
- "By August 15, I will have applied to 10 junior data analyst roles with a portfolio of 3 SQL + dashboard projects, measured by getting at least one phone screen."

If you can't write that line, the goal isn't clear yet. Ask one more question.

## Avoid

- Accepting "learn X" as a goal — it has no endpoint
- Asking more than 2-3 clarifying questions before proposing a clarified goal (analysis paralysis)
- Goals longer than 90 days for the first iteration — break them down
