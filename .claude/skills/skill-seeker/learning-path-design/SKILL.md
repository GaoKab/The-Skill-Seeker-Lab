# Learning Path Design

Run this after goal-clarification has produced a measurable 90-day target. Output a path with milestones at 30 / 60 / 90 days.

## Sequencing frameworks

Pick one:

- **Bridge** — current skill → bridge skill → target skill. Use when the user has a related skill that gets them halfway there. (e.g. SQL analyst → Python → data scientist.)
- **T-shape** — deepen one core skill, broaden 2-3 adjacent ones. Use when the user is mid-career and adding range, not pivoting.
- **Project-driven** — pick one concrete project, learn whatever that project demands, in order of need. Use when the user learns by building and the goal is a portfolio piece.
- **Credential-driven** — work backwards from a job spec or cert; the syllabus is the path. Use when the goal is a specific role or qualification.
- **Income-first** — learn the smallest skill that earns the first $1, then layer up. Use for freelance/career-change with financial pressure.

## Time-budget reality check

Before committing to a path:

- **Hours/week × weeks = total hours.** State this number explicitly.
- **Cap at 80% of stated availability.** People overestimate; leave slack.
- **If total < 60 hours**, the goal is probably too ambitious for 90 days. Narrow it.
- **If total > 300 hours**, the goal is probably more than 90 days. Phase it.

## Milestone heuristics

Each milestone must be a thing the user can show or test, not a topic they "covered."

- **30 days** — first artifact in hand (a working notebook, a deployed toy app, one finished course with a project, 3 cold outreach replies). Proves the user can produce, not just consume.
- **60 days** — second artifact, more ambitious; or first artifact applied in real context (used at work, shown to a peer, posted publicly).
- **90 days** — outcome from the clarified goal: the job applied to, the project shipped, the decision made.

## Tradeoffs to name explicitly

Every path has a cost. Name it:

- What the user is **not** learning by following this path
- Where the path will feel slow or boring (and how long that phase lasts)
- What's the most likely failure mode (e.g. "you'll get stuck on deployment around week 4")

## Output

Hand the path to the master skill, formatted to fill the master's output template. Don't return a recommendation directly from here.

## Avoid

- Padding with prerequisites the user doesn't need for their goal (e.g. "first learn linear algebra" for someone who wants to use ML libraries)
- Vague milestones ("understand fundamentals", "be comfortable with X") — replace with a thing they can show
- Sequencing more than 3 distinct skills in 90 days
- Recommending a path you wouldn't follow yourself in their position
